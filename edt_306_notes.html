Introduction to Learning Management Systems
Section 1
Definition

An LMS is a software platform designed to create, deliver, manage, and track educational content and learner activities. It is the digital backbone of modern e-learning used by schools, universities, and organisations to administer training at scale.

1.1 What an LMS Provides

  • Course enrolment and access control
  • Content delivery (text, video, documents)
  • Assessment management (quizzes, assignments)
  • A gradebook to track and record learner performance
  • Completion tracking and reports
  • Communication tools (forums, messaging)
Critical Distinction

A platform that only offers AI-based reading recommendations or discussion tools is NOT an LMS. An LMS must manage enrolment, record assessment results, and produce evidence of learning at scale. Collaboration tools alone do not make a platform an LMS.

1.2 Why LMS Matters

  • Standard tools in modern Nigerian tertiary education
  • Enable Computer-Based Testing (CBT) — the format used for many university exams
  • Allow lecturers to deliver courses flexibly, beyond classroom hours
  • Provide measurable, auditable records of student participation and performance

Overview of Moodle
Section 2

Moodle stands for Modular Object-Oriented Dynamic Learning Environment. Developed by Martin Dougiamas in 2002, it is the world's most widely used open-source LMS, powering over 300 million learners globally.

2.1 Key Characteristics

License
Open-Source (GPL)
Free to download and modify. Source code is publicly available.
Language
PHP
Written in PHP (server-side). Database: MySQL, PostgreSQL, MariaDB, or MS SQL Server.
OS Support
Linux, Windows, macOS
Linux recommended for production environments.
Hosting
Self or Cloud
Self-hosted or cloud-hosted via Moodle Cloud / MoodleNet.
Plugins
1,700+ Free Plugins
Available from the official Moodle Plugin Directory.

Open-Source vs. Proprietary LMS
Section 3
Feature Open-Source (e.g., Moodle) Proprietary (e.g., Blackboard, Canvas)
Cost Free to download and install Requires paid licences/subscriptions
Source Code Publicly accessible — full code-level modification allowed Restricted; customisation limited to vendor tools
Plugins/Themes Community-driven plugins and themes Built-in features pre-packaged by vendor
Maintenance Requires IT expertise to manage Vendor manages updates, hosting, and support
Scalability Can scale with proper configuration Designed to support large populations out-of-the-box
Key Test Point

The KEY distinction: open-source LMSs allow code-level modification, while proprietary LMSs usually restrict such access. This does NOT mean open-source always has more features — it means you have the freedom to change the code itself.

4
Moodle Deployment Options
Section 4
Option 1
Moodle Cloud
Fully hosted by Moodle HQ. No server setup. Automatic upgrades. Best for small classes, quick pilots, testing.
Option 2
Managed Hosting
Third-party hosts manage servers and upgrades. Best for schools wanting managed services without full IT overhead.
Option 3
Self-Hosted
Install Moodle on your own server (Linux recommended). Full control. Best for universities needing customisation and scalability.

4.1 Installation Methods

  • Installer Packages (e.g., MoodleWindowsInstaller / XAMPP bundle): Best for small/testing setups. Quick to deploy but less flexible.
  • Manual Install: Download source, configure web server + database separately. Preferred for scalable institutional deployments. Supports scripted, repeatable installation (command-line install).

Installing Moodle on Windows (Step-by-Step)
Section 5

In EDT 306 practicals, Moodle was installed locally on a Windows computer using the MoodleWindowsInstaller package — recommended for personal/pilot use.

5.1 Prerequisites

  • Windows 10 or 11
  • At least 4 GB RAM and 2 GB free disk space
  • Internet connection (for initial download)
  • Administrator privileges on your computer
1
Download the Installer
Go to https://download.moodle.org/windows/. Download the MoodleWindowsInstaller package (a .zip bundle that includes Apache, PHP, and MariaDB).
2
Extract the ZIP File
Right-click the .zip and select "Extract All...". Extract to a simple path — ideally C:\moodle. AVOID paths with spaces or special characters (e.g., C:\Program Files\...).
3
Run Start Moodle
Open the extracted folder and double-click Start Moodle.exe. Two terminal windows open — one for Apache (web server at http://localhost) and one for MariaDB (database). Leave both open.
4
Open the Browser
Navigate to http://localhost. If the installer wizard doesn't appear, try http://localhost/moodle.
5
Follow the Installation Wizard
Select language → Confirm paths (accept defaults) → Database settings (default user: root, no password) → Accept GPL licence → Server environment check (all green ticks).
6
Create Admin Account
Enter a username (e.g., admin), strong password, full name, and email. Remember these credentials — this is your master login.
7
Set the Site Name & Save
Give your Moodle site a name (e.g., "EDT 306 Course Site"). Provide a short name (used in breadcrumbs). Click Save Changes.
8
Stopping Moodle
Run Stop Moodle.exe or close the Apache/MariaDB terminals. Always stop properly to avoid database corruption.

Customising the Moodle Homepage
Section 7
Correct Workflow (Test Q12)

Login as admin → Site Home → Enable Editing → Configure front page settings → Add structured content → Save Changes
This is the ONLY correct sequence. Do not go through Reports, Users, or Courses.

1
Go to Site Home
Click 'Site Home' in the left navigation drawer.
2
Enable Editing
Click the 'Turn editing on' button (top-right). This reveals editing icons and controls.
3
Configure Front Page Settings
Click the Settings cog → 'Edit settings'. Set the full name, short name, summary, and what appears to logged-in/logged-out users.
4
Add Structured Content
Add Blocks (Calendar, HTML, etc.) via 'Add a block'. Add welcome text or category listings to the page body.
5
Save & Turn Editing Off
Click Save changes. Then click 'Turn editing off' so students see the clean view.

7.2 Adding a Welcome Activity with a Video

  • Enter the course → Turn editing on → Add an activity or resource → Choose 'Page'
  • Name it "Welcome to EDT 306" and write a brief welcome message
  • To add a video: paste the YouTube URL using "Insert media" or "Insert link"
  • Never upload video files directly — use a URL resource pointing to externally hosted video. This keeps Moodle storage lean and backups small.

Lecturer's 9-Step Lesson Setup
Section 9
1
Get Your Timetable Ready
Plan your lesson schedule before logging in. Example: Monday – Lecture, Wednesday – Practical, Friday – Quiz.
2
Prepare Content and Materials
Gather notes (Word/PDF), relevant photos, discussion forum topics, video links (YouTube URLs — not downloaded files), and quiz questions.
3
Log in to Moodle
Go to http://localhost or your institution's URL. Enter your admin/lecturer credentials.
4
Go to Site Administration
Click 'Site Administration' in the left navigation drawer. Only visible to admins and managers.
5
Go to Courses
Click 'Courses' to access management options: Manage Courses, Add a category/course, Default Settings, and Backup/Restore.
6
Go to Manage Courses and Categories
The central organiser for your Moodle site's course structure.
7
Create New Categories
E.g., "Junior Class" (100–200 Level), "Senior Class" (300–400 Level), "Undergraduate". Add 2–3 lines of description each.
8
Click the Relevant Category
Click the category name where your new course belongs (e.g., "Senior Class" for EDT 306).
9
Create New Course
Click "Create new course". Set Course Format: Weekly, Number of Weeks: 15, Start Date: First lecture day. Click "Save and display".

Adding Course Content & Activities
Section 10
Common Problem (Test Q18)

If a lecturer cannot find "Add an activity or resource", the most common cause is that Editing is NOT enabled. Simply click "Turn editing on" and the button will appear.

10.1 Adding a Discussion Forum

Correct Workflow

Turn editing on → Choose course section (e.g., Week 3) → Click "Add an activity or resource" → Select "Forum" → Configure settings → Save

Forum SettingWhat It Does
Forum TypeStandard (anyone starts a topic), Q&A (must post first), Single Discussion (one thread)
Group ModeFound in Common Module Settings. Options: No groups, Separate groups, Visible groups.
AvailabilitySet open and close dates for when students can post
Test Q13

Group mode is configured in Common Module Settings — at the bottom of any activity's settings page. Not in Site Administration or inside the post editor.

10.2 Adding a URL Resource (Video Link)

  • Turn editing on → Add activity or resource → Select "URL"
  • Enter a name (e.g., "Watch: Introduction to Moodle – YouTube")
  • Paste the full YouTube or video URL in the External URL field
  • Under Appearance, set Display to "Embed" or "Open"

10.3 Adding a File Resource (Lesson Notes)

  • Turn editing on → Add activity or resource → Select "File"
  • Name it (e.g., "Week 3 Lesson Note – LMS Overview")
  • Drag-and-drop or upload your PDF/Word document

Quiz Configuration & Academic Integrity
Section 11
Critical Distinction — Open/Close Dates vs. Time Limit

Open/Close Dates: Control WHEN attempts may begin (like the exam room door). Setting: 8:00 AM opens — 10:00 AM closes.

Time Limit: Controls HOW LONG a student has once they START (e.g., 30 minutes from when they click "Start Attempt").

These are INDEPENDENT settings. Setting one does NOT automatically set the other.

11.1 Practical Example

  • Quiz opens: 8:00 AM Friday; Closes: 10:00 AM Friday; Time limit: 30 minutes
  • Student starting at 8:00 AM has until 8:30 AM
  • Student starting at 9:45 AM has until 10:00 AM (close date cuts them off)
  • Student visiting before open date sees the introduction but cannot attempt

11.2 Quiz Creation Steps

1
Add the Quiz Activity
Turn editing on → Add activity or resource → Select "Quiz".
2
Configure Timing
Enable Open/Close dates. Enable Time Limit (e.g., 30 minutes). Set "When time expires" to "Open attempts are submitted automatically".
3
Configure Attempts & Behaviour
Attempts allowed: 1 (for exam conditions). Question behaviour: Deferred feedback. Shuffle questions: Yes. Shuffle within questions: Yes.
4
Add Questions
Click "Edit quiz" → "Add" → "a new question" or "from question bank". Types: Multiple Choice, True/False, Short Answer, Essay, Matching.

11.3 User Overrides for Accessibility

Test Point

Use User Overrides (not Group Overrides) when accommodation is for one specific individual. Path: Inside the Quiz → Quiz Administration → User Overrides → Add Override → Select the student → Set their specific time limit.

11.4 Academic Integrity (LMS-Centred Approach)

  • Shuffle questions and answers to reduce cheating
  • Set strict time limits and allow only one attempt
  • Use Moodle's attempt logs (records exactly when and what each student answered)
  • Controlled settings + recording attempts = LMS-centred integrity (Test Q14)
